## 端口最终定在 18062（8062 → 18062）

**背景**：用户提出「端口要不容易被占用，但固定下来其他项目都得改」。这句话里的成本判断需要核实，
核实后发现问题另有真相。

**关键调研结论（推翻了上一轮的两个假设）**：
1. **真正的风险源是 Windows 动态端口范围 = 1024~15000**（本机被 Docker/WSL 改过，默认应是 49152 起）。
   80xx 段全在这个池里，会被系统当临时端口随机分配 → 这才是「端口容易被占用」的机制。
   18062 > 15000，天然在池外。
2. **duihuamoxing 已彻底搬离 8060**：它的 `启动.bat` 用 8061、`文字驱动语音/启动.bat` 用 18060、
   `tts-18060-task.bat` 用 18060。8060 被占的根源已消失（8060 上那个实例是遗留进程，本次也已退出）。
3. **唯一依赖方是 `D:\xm\zhuomianchunwu\airi`（桌面宠物 AIRI）**，指向 8060 共 19 处。
   而 8060 上跑的是 duihuamoxing 的副本 → **airi 从来没用上本项目的服务**（隐性错配）。
   曾误以为「airi 只改 2 处」——实际 `mine.vue` 里还有一处 `TTS_BASE` 硬编码，
   第一遍扫描（只搜 8062/wenziqudong）漏掉了它。

**决定**（用户拍板）：端口改 **18062**；airi 由我代改。

**改动**：
- wenziqudong：8062 → 18062，共 **72 处**（tts_api.py / start.bat / stop.bat / tts_watchdog.ps1 /
  tests×3 / README / DEPLOY / 部署方案 / 接口文档 / AGENTS）
- 6 处过时说明重写（原「8060 属 duihuamoxing」→「18062 在动态端口范围外；duihuamoxing 用 8061/18060」）
- airi：**19 处** 8060 → 18062，含 `apps/stage-web/vite.config.ts`（代理）、
  `packages/stage-ui/src/stores/providers.ts`（默认 baseUrl）、
  **`apps/stage-web/src/pages/mine.vue`（TTS_BASE 硬编码）**、
  `apps/data/local-auth-db.json`（浏览器本地存储实际地址）、`DEPLOY.md`、若干注释；
  `docs/测试记录.md` 属历史记录未动

**服务状态**：旧实例（看门狗 10140 / python 30636）已停止，8062 已释放，pid 文件已清。
**因安全策略（Start-Process / cmd.exe 均被拦）无法代启动 .bat，需用户双击 `start.bat`**
在 18062 上重启（首次加载 5-10 分钟）。18062 已验证可绑定（空闲）。

**待办**：建议管理员执行一次端口保留作双保险（18062 本就在动态池外）：
`netsh int ipv4 add excludedportrange protocol=tcp startport=18062 numberofports=1`

**教训**：跨项目改端口前，搜索必须覆盖「端口号」「项目名」「硬编码 URL」三类线索，
且 xargs 管道遇中文路径会静默丢文件——用 Python 遍历才可靠。
